## 1. 场景：一栋多层仓库

想象一栋几层楼的仓库（楼层数 $F$），里面有：

- **一队搬运机器人**（AMR，共 $A$ 台），负责把货物从一个地方搬到另一个地方；
- **几部货梯**（$E$ 部），每部电梯只有一个**轿厢**（car），也就是在井道里上下跑、装机器人的那个厢体。

关键限制是：**机器人要换楼层，只能坐电梯**。楼层内的移动不成问题，一到跨楼层就得排队等电梯。电梯数量少、大家都要用，所以电梯是整个仓库的"瓶颈"。论文题目里的"垂直资源约束"说的就是它。

## 2. 任务：订单，以及把订单打包成"波次"

每个**订单**（order）就是一件搬运任务，比如"把一箱货从 1 楼搬到 3 楼"。它有三个信息：

- 起始楼层 $s_o$：从哪层取货；
- 目标楼层 $d_o$：送到哪层；
- 就绪时间 $r_o$：从释放时刻算起，什么时候可以开始做。在 uniform 和 clustered 两种需求模式下，所有订单一释放就能做（$r_o=0$）；在 diurnal 模式下，就绪时间分散在 0 到 50 秒之间。

仓库管理系统（WMS）不是来一单派一单，而是**攒一批一起放出去**，这一批就叫一个**波次**（wave）。每个波次的订单数固定为 $n$ 个。

## 3. 要做的决策：放哪一批出去

这是论文研究的核心问题。

手头有一个订单池（每个配置 600 个订单）。系统从中随机拼出 $K$ 个可能的波次作为候选池，发表规模为 $K=3000$。现在要决定：**释放哪一个波次**。

为什么这个选择重要？因为同样是 $n$ 个订单，**组合不同，电梯的忙碌程度完全不同**：

- 如果这批订单集中在少数几层之间、方向一边倒，电梯可能在某些楼层严重排队；
- 如果订单分散、上下行均衡，电梯可能用得更顺。

**衡量好坏的标准**是完工时间（makespan）：从波次释放，到最后一个订单送达，一共用了多久。越短越好。

注意分工：论文只研究**"放哪批"这一层决策**（战术层）。机器人怎么派、电梯怎么调度（运营层）用一套**固定规则**，不去优化它。这样才能单独看清"波次组成"本身的影响。

## 4. 一个订单是怎么被执行的（对应图 3.1(b)）

系统按固定顺序一个一个处理波次里的订单。每个订单的流程是：

1. **派车**：找最早空闲下来的机器人；
2. **等订单就绪**：如果订单还没到可以做的时间，机器人就等着；
3. **去取货楼层**：如果机器人不在取货那层，要先坐电梯过去；
4. **取货**：花固定时间 $\tau^P$，楼层内走过去的时间也算在里面；
5. **载货坐电梯**：如果起点和终点楼层不同，就叫电梯、等电梯、坐电梯；
6. **卸货**：花固定时间 $\tau^D$，送达。

其中"坐一趟电梯"又分成几段：先**等轿厢做完手上的活**，轿厢**空跑到取货楼层**，**装载**（开门让机器人进去），**运行**到目标楼层，**卸载**。

同层订单（比如图里的 $o_3$，2 楼到 2 楼）的货物不用坐电梯。

这里的计算方式是**"逐单预约"**：一单一单地往时间表上排，而不是模拟所有机器人同时乱跑的真实过程。好处是计算快、结果确定，同样的输入永远得到同样的完工时间。第 5 节用一个"真实并发"的事件驱动仿真检验了这种简化。

## 5. 最大的不确定性：电梯到底怎么载机器人？

电梯容量是 $c$（发表规模 $c=2$，即一个轿厢能装 2 台机器人）。但"能装 2 台"在现实里意味着什么，可以有不同理解。论文用三种"评估器"（elevator model）来表示：

- **$M_1$（吞吐抽象）**：把 $E$ 部容量为 $c$ 的电梯，看成 $E\times c$ 个**互不相干的单人通道**。每个请求独占一趟完整行程，谁也不跟谁拼，是一种偏乐观的"总运力"视角。
- **$M_2$（真实同乘）**：$E$ 个实体轿厢，**可以拼梯，但条件严格**：
  - 两台机器人的起点楼层和终点楼层都相同；
  - 轿厢里还有空位；
  - 后来的那台在"关门"（装载结束）之前赶到。
- **$M_3$（带随机波动的同乘）**：规则同 $M_2$，但每趟电梯各段的耗时会随机波动，时快时慢（$\sigma=0.20$）。

论文假定：**做决策的时候，你不知道现实更接近哪一种**。所以选波次时不能只按某一个模型来选，要考虑模型不确定。

## 6. 怎么"选波次"：先把波次分类

直接从 3000 个候选里挑一个最优的，这个挑法只对这一个候选池有效，换一批订单就没意义了。所以主模型换了个思路：**先给波次分类，再选"哪一类"**。

分类用两个直观指标（描述子 $\Phi$）：

- **$C$（楼层分散度）**：这批订单的起终点楼层分布得有多散。$C$ 高表示分布在很多楼层，低表示集中在少数几层。
- **$I$（方向不平衡度）**：上行和下行订单是否一边倒。接近 1 表示几乎全往一个方向，接近 0 表示上下均衡。
- 另有 $T$（就绪时间离散度），只用于补充分析，不参与分类。

然后按 $C$ 高或低、$I$ 高或低，取两个指标各自的尾部（尾部概率 $\alpha=0.25$），得到四个**角类**：HH、HL、LH、LL。例如 HL 就是"楼层很分散、方向很均衡"的那一类波次。

**选定一个类，就是从这一类里随机抽一个波次释放。**另外还有一个"参照类"：从整个候选池随机抽，作为比较基线，它不是决策选项。

## 7. 目标：选"最坏情况下也最好"的那一类

- 每一类的表现，用该类波次完工时间的**中位数**来衡量。
- 因为不知道电梯是 $M_1$ 还是 $M_2$，对每一类都看它在 **$M_1$ 和 $M_2$ 下哪个更差**，然后**选"更差的那个"最小的类**。这就是"稳健选择"（min-max）。
- $M_3$ 不参与这个选择，只用来检验选出来的类在电梯时间波动下还站不站得住。

另有一个**标杆**：在某个电梯模型下，把 3000 个候选逐个算一遍，找出完工时间最短的那一个（池内最优）。任何"选类"的方法都不可能比它更好，所以它是下界，用来衡量"选类"离最好还差多少。

## 8. 为了能算，做了哪些简化（假设 A1 至 A6）

- **A1**：只看一个波次。开始时所有机器人和电梯都停在同一层（$f^0$，代码中为 1 楼），没有上一波遗留的活。
- **A2**：一台机器人一次只搬一单，谁取的货谁送。
- **A3**：订单的楼层和就绪时间事先已知。
- **A4**：楼层内的走动和装卸，用固定的取货和卸货时长代替，不模拟楼层内的路径和拥堵。
- **A5**：一趟电梯只服务一对起终点，中途不停；运行时间和经过的楼层数成正比。
- **A6**：电梯的表示方式不确定，所以要在多个模型下评价。

这些简化的代价要心里有数。与并发的事件驱动仿真相比，闭式评估器约高估完工时间 25% 至 37%。按完工时间给波次排序，两者的一致性 Spearman $\rho$ 约为 0.45 至 0.68，没有达到预设的保真门槛。"$M_2$ 不比 $M_1$ 快"这个方向性结论大体保留，但逐个波次的排序不能直接外推到真实系统。

## 9. 这个设定和三项贡献怎么接上（按 2026-09-03 主控口径）

- **C1：固定运营规则下的单波选择问题与基准。**第 3 节把"放哪一批"写成一个清楚的决策问题：选类、稳健选择、池内最优标杆，以及共同的二元规划形式。它不是完整的滚动时域调度器。
- **C2：模型占优的条件结果与对冲规则（Hedge Rule）。**
  - 如果同一个波次在 $M_2$ 下的完工时间总是不短于 $M_1$（称为"占优"），那"两个模型取最坏"就总是取到 $M_2$，稳健选择就等于"按 $M_2$ 选最好的类"。
  - 论文给出占优成立的充分条件，也分析了占优失败的两类机制。
  - 充分条件本身很严，只在不到 1% 的波次上成立；但在发表规模的闭式模拟中，逐波次比较平均有 99.2% 的波次满足占优。这是经验规律，不是定理的命中率。
  - 按这条规则选类，实际代价在 6 个配置中有 5 个为 0，1 个为 2.63%。
- **C3：经验强度与有效性边界。**用预注册实验量化上述规律有多强、对冲的实际代价有多大，以及诊断指标对分类方式、随机种子、重复抽样和仿真保真度有多敏感。其中的"界与差距"（Bound-and-Gap）诊断记号如下：
  - $b_+$：最差类的中位完工时间；
  - $b_-$：最好类的中位完工时间；
  - $b_0$：随机释放（参照类）的中位完工时间；
  - $b_{q_\Phi}$：按描述子规则选中的类的中位完工时间。
  
  它把差距拆成两部分：
  - $H_{\mathrm{up}}=(b_+-b_0)/b_0$：最差的类比随机释放差多少，即"选错类会有多糟"；
  - $M_\Phi=(b_{q_\Phi}-b_-)/b_0$：选中的类比最好的类差多少，即"选类失误"。
  
  $H_{\mathrm{up}}$ 占差距的份额，预注册口径约 72%，covering 口径约 47%。两者都只是**相对于所用分类方式的读数**，不代表"电梯容量是瓶颈"，也不能据此建议增购电梯；重复测量的一致性也很差（ICC 约 0.01）。另一个边界发现：把运营层调度换成"同起终点订单成组派发"，平均可改善约 10.2%，大于战术层选波平均约 6.0% 的差距。

## 一句话总结

**一栋靠少数几部共享电梯连接各层的仓库里，机器人要成批完成跨楼层搬运。管理者决定每次放出哪一批订单，使这批活干完的时间尽量短。难点在于：电梯是瓶颈，而且我们并不确定电梯"拼梯"的真实规则是什么样。**

## 补充问答

### 问 1：设定了哪几个不确定的量？

**真正被当作"不确定"来处理的只有两项，都与电梯有关：**

| 不确定量 | 含义 | 模型中的处理 |
|---|---|---|
| 电梯容量**如何起作用** | 容量 $c=2$ 是按"$E\times c$ 个独立通道"起作用（$M_1$），还是按"同起终点才能拼梯"起作用（$M_2$） | 决策时不知道哪种成立，用 min-max 在 $M_1$、$M_2$ 之间做稳健选择 |
| 电梯行程各段耗时的**随机波动**（仅 $M_3$） | 空驶调位、装载、运行、卸载四段各乘一个随机乘子，对数正态分布，均值为 1，$\sigma=0.20$ | 只用来检验所选类别的稳健性，不参与选择；等待时间本身不加乘子，只因前面行程变快变慢而间接变化；取货、卸货时间不波动 |

**还有两种"随机性"，但不是决策面临的不确定性：**

- **类内抽到哪个波次**：选定一类后，从类内均匀随机抽一个释放。这是设计出来的随机，因此一个类的表现是一个分布，用中位数衡量。
- **订单池和候选波次是随机生成的**：这是实验样本的随机性。一旦生成，在决策时刻全部已知。

**你提到的两个例子：**

- **截止时间：没有。**模型里没有交期或截止时间，目标是总完工时间，不是延误。
- **轿厢容量：数值是已知且固定的（$c=2$）。**不确定的是容量"怎么被用上"，而不是容量有多大。

订单的起终点楼层、就绪时间、机器人和电梯数量、运行速度、装卸时长，在第 3 节主模型里都是已知的。代码里另有几个扩展开关（取货卸货时间波动、电梯换向惩罚、不同容量轿厢混用），只用于附录的稳健性检验，不属于第 3 节主模型。

### 问 2：哪些量是固定的？

**参数（发表规模取值）：**

| 量 | 符号 | 取值 |
|---|---|---|
| 楼层数 | $F$ | 3、5、8 |
| 机器人数 | $A$ | 5、15、30 |
| 电梯数（每部一个轿厢） | $E$ | 1、2 |
| 轿厢容量 | $c$ | 2 |
| 需求模式 | | uniform（起终点均匀）、clustered（20% 的楼层对承担 80% 的订单）、diurnal（就绪时间集中在一个高峰窗口） |
| 配置数 | | 以上因子的 1/3 部分因子设计，共 18 个 |
| 订单池规模 | | 每个配置 600 单 |
| 候选池规模 | $K$ | 3000 |
| 波次规模 | $n$ | 8 或 30（Block A、B），16（Block C） |
| 电梯每层运行时间 | $\gamma$ | 5 秒/层 |
| 装载、卸载时间 | $\tau^L,\tau^U$ | 各 2 秒 |
| 取货、卸货服务时间 | $\tau^P,\tau^D$ | 各 5 秒 |
| 释放时刻、初始楼层 | $t_W$、$f^0$ | 0 秒、1 楼 |
| 尾部概率 | $\alpha$ | 0.25 |
| $M_3$ 波动幅度 | $\sigma$ | 0.20 |
| 就绪时间 | $r_o$ | uniform 与 clustered 全为 0；diurnal 分布在 0 至 50 秒，其中 70% 落在一个 15 秒的高峰窗口内 |

**规则（运营层固定不变）：**

- 订单按候选生成时记录的顺序 $\pi^k$ 依次处理；
- 每单交给最早空闲的机器人，同时空闲时按编号；
- 能拼梯时选编号最小的合格轿厢；不能拼时在最早空闲的轿厢上开新行程，同时空闲按编号；
- 选定类别后在类内均匀随机抽取波次；
- 类别表现用中位数衡量；
- 开始时所有资源都在 1 楼、空闲。

### 问 3：机器人和电梯的先后顺序是怎样的？一次性接送还是分批接送？

**不是"先把机器人送到各楼层，再统一接回"。**模型里没有预先布置机器人的阶段，也没有回库。

**机器人这边：**

- 订单按固定顺序逐个分配，每单交给当时最早空闲的机器人。
- 一台机器人一次只做一单，从头到尾自己完成：（需要时）坐电梯去取货层，取货，（需要时）载货坐电梯，卸货。
- 做完后它就停在送达的楼层。下一单如果起点在别的楼层，它再坐电梯过去（空车调位）。
- 多台机器人的工作在时间上是**重叠、并行**的。比如有 5 台机器人时，前 5 单在释放时刻同时开工。
- 如果订单多于机器人（如 $n=30$、$A=5$），每台机器人会先后做好几单。

**电梯这边：**

- 每趟电梯只服务一对起终点，中途不停。它不像公交车那样沿途在多个楼层接人。
- 轿厢做完一趟就停在终点层，下一趟要先空跑到新的起点层。
- 一台机器人完成一单，最多坐两趟电梯：一趟空车去取货层（不在那层时），一趟载货去目标层（跨楼层时）。

**一次性还是分批：看电梯模型。**

- **$M_1$**：不拼梯，每个请求独占一个"通道"跑完整趟；但有 $E\times c$ 个通道可以并行。
- **$M_2$、$M_3$**：可以拼，一趟最多 $c=2$ 台。条件是起点相同、终点相同、还有空位、后来者在关门（装载结束时刻 $L_e$）之前赶到。空车去取货的机器人和载着货的机器人都算，只要起终点一致就能同乘。否则开新的一趟。
- 拼梯是"碰上了就拼"：默认规则不会让轿厢刻意等人，也不会重排订单去凑单。
- 第 5 节另测了一种"聚类调度"：把起终点相同的订单（最多 $c$ 个）排在一起连续派发，增加拼梯机会，平均改善约 10.2%。它只作为单独标注的稳健性检验。

**逐单预约带来的一个细节：**订单是一个一个登记到时间表上的。先登记的请求先占用电梯；后登记的请求即使实际发生时间更早，也不能插到已登记的行程前面。这是闭式评估器的简化，第 8 节末尾给出了它与并发仿真的差距。

**以图 3.1 为例，订单 $o_1$（1 楼到 3 楼），假设电梯空闲、无需等待：**

| 时刻 | 发生的事 |
|---|---|
| 0 秒 | 机器人在 1 楼开工，走到货架 |
| 5 秒 | 取货完成（$\tau^P=5$），呼叫电梯；轿厢就在 1 楼，无需空跑 |
| 7 秒 | 装载完成、关门（2 秒） |
| 17 秒 | 运行 2 层到 3 楼（2 层 × 5 秒） |
| 19 秒 | 卸载出轿厢（2 秒） |
| 24 秒 | 走到卸货点、卸货完成（$\tau^D=5$） |

对比另外两单：
- $o_3$（2 楼到 2 楼）的货物不坐电梯，但机器人从 1 楼出发，要先坐一趟空车电梯到 2 楼。
- $o_2$（$F$ 楼到 2 楼）要坐两趟：先空车上到 $F$ 楼取货，再载货下到 2 楼。
