## Findings made while checking the drafts against code and stored results

1. **Local search is much stronger than every class rule.** P7 (median of 200 runs of 40 iterations) is below P8 in 12/12 Block B cells (grand means 224.6 against 288.4; P5 303.6). The v2 plan compared GSV with "P7" and described the procedure as "matching search at a fraction of the evaluations", which is wrong: GSV uses 6,200 closed-form evaluations plus k DES runs. The protocol now compares GSV(20) with a **budget-matched multi-start local search (P7-matched)** that gets the same 6,200 M2 evaluations and the same 20 DES verifications. The Phase 5 single-run P7 is kept as a descriptive arm.
2. **Seed collision avoided.** The rule "pool seed = S_p + config_id" would give pool p + 1 of configuration c and pool p of configuration c + 1 the same seed; configurations 2j and 2j + 1 differ only in E, so these pools would be identical. The protocol uses the Phase 5 mixing formula instead.
3. **Ties.** Integer makespans produce ties at the top of rankings. The protocol breaks every tie by a fixed random permutation (stream 98) rather than by index, which would favour the random candidates listed first. DL_m uses the mean over tied optima.
4. **Generator ablations** (GSV on R only, on R ∪ P10(R), on R ∪ P11) are registered as descriptive rows computed from the same enumeration, so the value of the constructor can be attributed without adding forking paths. The headline stays GSV(20) on the full generated set.
5. **G1 wording.** The earlier upper-tier wording "recovers most of the clustered-dispatch gain" compared a DES quantity with a closed-form one. Reworded to describe the DES reduction on its own scale.
6. **DES ready times.** The B-5 cross-check had no diurnal configuration; ready times were exercised only by the single-AMR self-tests. The protocol's code-freeze checks now include multi-AMR ready-time tests.
7. **Case study ready times.** Invoice timestamps are customer order times hours apart, not intra-wave readiness. D-K and the protocol now use zero ready offsets in the primary case run and rank-scaled invoice times only as a sensitivity run.
8. **B-4 detail.** AMEND-B did not fix the heterogeneous capacity pair. The execution note proposes (1, 3) for E = 2, keeping the total capacity of (2, 2), as in the prototype's same-total spread.
9. **Registration history (for the honest statement).** The Phase 5 preregistration first entered git in commit `2c47cc5` together with the Phase 5 results, and its last modification time (2026-05-19 23:19 +0900) is later than the raw result files. The 2026-07-08 amendments are not tracked by git. See `archive_package/README_OSF.md` §3.
10. **Uncommitted code.** `simulator.py` (tie-break fix), `wave_policies.py` (empty corner raises), `experiments_phase5.py` and `experiments_phase5_supp.py` (candidate ids) carry uncommitted 2026-09-11 changes. The manifest's code-tree hash records the current state.
